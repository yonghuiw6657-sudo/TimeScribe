### P0 发现并修掉的真问题（都是"不测就发现不了"的）

| # | 问题 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | `.bat` 里写中文注释 | cmd 按 ANSI 解码，`@echo off` 失效、脚本逐行回显甚至报"文件名语法不正确" | **批处理文件只用 ASCII**；`tests/fix-bom.mjs` 会强制检查并拒绝非 ASCII |
| 2 | `.bat` 带 UTF-8 BOM | cmd 把 BOM 当命令的一部分，`@echo off` 变成 `?@echo off` | **`.bat` 绝不加 BOM**；`.ps1` 必须加 BOM（否则 PowerShell 5.1 下中文乱码）。`fix-bom.mjs` 自动纠正 |
| 3 | `for /f ... in (`` `"..." -File "..."` ``)` 内联引号 | cmd 解析失败，脚本从未被执行，退出码却是 0 | 改用 `call` 包一层；并把逻辑收敛到 PowerShell，`.bat` 只做转发 |
| 4 | 中文路径传给 `powershell -File` | 路径被 ANSI 解码弄坏，报"文件名、目录名或卷标语法不正确" | **入口脚本改成 ASCII 文件名** `launch.ps1`（双击用的 `启动.bat` 保持 ASCII 转发） |
| 5 | `Test-PortBusy` 只测 TCP 端口 | Windows 的 **HTTP.sys 会在 HttpListener 进程退出后继续替该端口接受连接**，于是每次双击都被误判为"已在运行"，真正的服务永远起不来 | 新增 `Test-ServerAnswering`：必须取到真实 HTTP 响应且内容匹配才算"已在运行"；端口被别的程序占用时明确报错 |
| 6 | `Start-Process -RedirectStandardOutput` 会阻塞父进程 | 输出管道被子进程持有，`启动.bat` 卡到超时（退出码 null） | `start-server.ps1` 只负责拉起并打印 PID，不等就绪；由调用方轮询端口 |
| 7 | 旧版 `serve.ps1 -Quiet` 静默失败 | 端口被占时"双击了但什么都没发生"，无从排查 | 失败写入 `server.log`；`server.pid` 记录真实进程号 |
| 8 | 测试自己留下的服务进程 | 端口残留 + HTTP.sys 预留，污染后续测试 | 测试结束显式 `taskkill` 服务进程并轮询确认端口释放（写成一条测试） |
| 9 | 静态检查规则过粗 | 把测试文件里的字符串（`http://0.0.0.0`）当成"外部引用"，误报 | 拆成两条：交付文件**完全不许有网络引用**；全目录**按主机名分类**，只禁止外部主机（本机地址除外） |
| 10 | 浏览器测试页没加载 app | DOM 断言全落空（测试页自己查不到 `#app`） | 改为同源 iframe 加载真实 app 再断言 |

### 已知环境限制（记录在案）

- `HttpListener` 场景下 `netstat -ano` / `Get-NetTCPConnection` 可能把监听者显示为 **PID 4（System/HTTP.sys）**，而不是真实的服务进程。因此：
  - 测试改为用 `server.pid` + `Get-Process` 校验"进程真实存在"；
  - 清理端口时同时按 `server.pid` 杀进程。

**关键结论（写进实现的约束）**

- **坏数据不白屏**：JSON 解析失败时，把原文另存到 `timetracker.corrupt.<时间戳>`，然后返回一份干净的空数据，界面照常启动。
- **旧数据自动补默认值**：缺 `settings` / `ui` 也能读，不需要写迁移脚本。
- **孤儿记录一律丢弃**：`projectId` 指向不存在项目的记录会被剔除并计数；父项目不存在的子项目会被**提升为顶层**而不是消失；出现第三层会被**压平成顶层**。
- **超长输入在这里兜底**：项目名截断到 30 字、备注截断到 100 字，界面不会因为脏数据被撑破。
- **配额不足抛可识别的 `QuotaError`**，与其他错误区分开，界面据此提示"请先导出备份"。
- **导入校验必须够严**：非本 app 文件、更新版本、缺列表、内容全部无法识别——一律拒绝且**不改动任何现有数据**（避免"导入一份空文件把用户数据清空"）。
- **测试清单与加载清单必须一致**：加了一条测试，比对 `manifest.json` 的全局模块、`index.html` 的 script 标签、`tests/selftest.html` 的 script 标签三者一致，防止测试环境和真实环境脱节。

**产物**：`js/storage.js`、`js/store.js`、`tests/manifest.json`。

## P2 · 时间与计算工具

**结果：全部通过**

| 测试文件 | 数量 | 结果 |
| --- | --- | --- |
| `tests/p2-format.test.js`（时长格式、时钟、日期、周边界、专注度） | 14 | 通过 |
| `tests/p2-summary.test.js`（统计汇总、扇形图分组与百分比） | 13 | 通过 |

**产出**：`js/calc.js`（全 app 唯一的统计口径来源）。

**关键结论**

- **日期一律用本地时区**：`toDateStr` 自己拼 `YYYY-MM-DD`，绝不使用 `toISOString()`（UTC 会差一天）。测试专门验证了本地 00:30 这种边界。
- **一周从周一开始**：测试覆盖周一当天、周日当天、跨月、跨年（2025-01-01 属于 2024-12-30 开始那一周）。
- **先四舍五入到分钟、再拆分小时**：3599 秒必须显示成 `1 小时`，不能是 `59 分`。
- **扇形图百分比用最大余数法**：保证各块相加**正好 100%**，不会出现 99% 或 101%。
- **专注度只认计时产生的记录**：手动补录没有暂停数据，算进去会把专注度虚高，因此 `source === 'manual'` 的记录不参与专注度，但仍计入累计投入。
- **孤儿记录一律忽略**：统计不会因为一条脏数据而变形。
- 测试里所有日期都**相对"今天"动态生成**，因此在任何一天运行都成立；另有一条测试遍历周一到周日，验证"今天/本周"的口径每天都正确。

**测试自身也出过两次错**（记录在案，说明为什么必须逐条核对而不是"看一眼差不多"）：
1. 我把"本周"期望写少了一条——手动补录记录同样落在本周内。
2. 我把"专注度"期望写成了不含手动补录的 1800，实际该项目另有一条上周的计时记录 900 秒也应计入。

两次都是**修正测试期望**（实现是对的），并补了注释说明口径，避免以后又改错。

**测试运行机制的重要修正（记在案，避免重蹈覆辙）**

- `--dump-dom` 在页面脚本还没跑完时就会取走 DOM（结果只剩 `RUNNING`）。
- 加 `--virtual-time-budget` 能等到结果，但**虚拟时间下 `setTimeout` 几乎瞬时触发、而 `Date.now()` 仍走真实时间**，两者脱节会让"计时时长"类断言失去意义（P4 一开始就是这么错了一次）。
- 最终方案：**测试页把结果 POST 到本机服务的 `/__result`，运行器轮询取回**。不做虚拟时间，计时测试跑在真实时间上。
- 另外发现：残留的服务器进程会在 HTTP.sys 里留下端口预留（`netstat` 显示 PID 4），导致新服务"看起来在跑、实际是旧的"。已用 `netstat` 清理并强制测试结束时回收。

## 第二轮修正：切后台不该暂停、关闭即结算

**来自实际使用反馈**：用了之后发现"切出浏览器再回来，计时变成了暂停"。

### 根因（我的设计错误）

`main.js` 的生命周期处理里，把**"切走浏览器"**（`visibilitychange` → hidden，切标签、切到别的应用、最小化都会触发）
和**"关闭页面"**（`pagehide`）接到了同一个处理函数上，而那个函数会把计时改成"暂停中"。
结果就是：只要切走一次，计时就被暂停了。

### 改成什么

| 时机 | 行为 |
| --- | --- |
| 切走浏览器 / 切到别的应用 / 最小化 | **不算中断**：计时按时间戳继续走；顺手把进度写进存储（心跳），便于被强杀时兜底 |
| 关闭页面 / 关闭浏览器 / 关掉应用 | **这一段直接结束**：结算到关闭那一刻，够阈值就保存成记录，不够就丢弃；不留"暂停中"的段 |
| 浏览器被强杀（没走正常关闭） | 下次打开时按**最后一次落盘时刻**结算并保存（绝不补算到"现在"），并明确告知用户 |

配套改动：

- 新增**心跳**：计时中每 15 秒把一次进度快照静默写进存储（`TTStore.patch`，不触发重绘）。
  这样即使被强杀，损失最多一个心跳间隔，而不是整段。
- 关闭时**不提供"撤销"**（页面马上就没了，撤销没有意义）；手动点"停止"仍然有撤销。
- `handlePageHide` 改名为 `finalizeOnClose`，语义从"改成暂停"变为"结束并保存"。

### 顺带堵住的一个隐患：同一段被记两次

改动"关闭即结算"之后，出现了一个新的现实风险：
**计时中如果你又双击了一次 `启动.bat`**（Edge 会再开一个页面），
第二个页面启动时会看到存储里那段"进行中"的现场，于是把它结算保存；
而第一个页面内存里还在继续计时，稍后停止时又会写一条——同一段时间被计了两次。

修法：**每段计时带一个唯一编号（`segmentId`）**，记录 id 由它推导（`rec-<segmentId>`），
写入时若同 id 已存在就跳过；存储层读取时也会对重复 id 去重。
这样即使两个页面都结算同一段，也只会留下一条记录。

### 新增/调整的自检用例（`tests/p4-timer.browser.test.js`，12 项 → 21 项；`p1-data.test.js` +1）

- 切走浏览器不会暂停，且在后台继续累计（直接调用 app 真实接线的那两个处理器：`__TT_HANDLE_HIDDEN__` / `__TT_HANDLE_CLOSE__`）
- 切到后台会刷新存储里的"最后落盘时刻"，心跳间隔在合理区间
- 关闭页面：够阈值保存、只算到关闭那刻、关闭后的等待不被补算
- 关闭页面：不足阈值直接丢弃，不留残留
- 真实刷新页面：那一段被结算成记录，不再有"暂停中"
- 暂停中关闭：已投入的部分照样保存
- 空闲时关闭：不产生记录、不留残留
- 异常退出：只按最后落盘时刻结算（20 秒而不是 30 秒），且会告知用户
- 异常退出且不足阈值：丢弃并提示
- **同一段被重复结算只记一条**（模拟"又开了一个页面"）
- 存储层：重复的记录 id 只保留第一条

**结果：全量 Node 86 + 浏览器 141 = 227 项全部通过。**

## 第三轮：项目改名（我的时间账本 → TimeScribe）

**改动范围**

| 位置 | 变化 |
| --- | --- |
| 文件夹 | `我的时间账本\` → `TimeScribe\` |
| 界面标题与顶栏 | `我的时间账本` → `TimeScribe` |
| 导出文件名 | `时间账本-2025-06-11-1405.json` → `TimeScribe-2025-06-11-1405.json` |
| 说明文档与开发文档 | 产品名统一为 TimeScribe |
| 内部标记 | `__TIMETRACKER_BOOT__` → `__TIMESCRIBE_BOOT__`；`data-app="timescribe"` |

**必须处理的兼容问题（不处理就会丢数据 / 旧备份作废）**

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 数据存储键从 `timetracker.v1` 变成 `timescribe.v1`，直接改键会让**已记录的时间全部"消失"** | 读取时若新键为空而旧键有数据，**自动搬到新键**；**旧键保留不删**；新键已有数据时不覆盖 |
| 2 | 导出文件的 `app` 标识从 `time-tracker` 变成 `timescribe`，直接改会让**改名前的备份无法导入** | 导入校验**同时接受新旧两个标识** |
| 3 | 导入前快照、损坏数据备份的键前缀也变了 | 读写时**同时认新旧两种前缀** |
| 4 | **服务自检是靠"页面里有没有旧名字"判断的**（`Test-ServerAnswering` 匹配 `timetracker`） | 改名后它认不出自己的服务，启动链路直接坏掉（双开判定、幂等性都失败）。改为匹配**稳定的页面标记** `data-app="timescribe"`，并兼容旧标记 |

第 4 条是这次改名中**唯一被自检抓出来的真实故障**——如果只做文本替换、不跑测试，
`启动.bat` 会从"能开"变成"能开但每次重新起服务 / 报端口被占用"，属于那种"用户不会专门报、但一直在坏"的问题。

**新增的自检用例**

- `p1-data.test.js`：旧数据键自动迁移且旧键保留；新键有数据时不被旧键覆盖；
  改名前的导出文件（`app: time-tracker`）仍可导入；导出用新标识且旧标识在兼容列表里
- `p9-data.browser.test.js`：改名前的导入前快照（旧键）仍能退回；改名前的备份仍能导入
- `p0-static.test.js`：说明文档内容检查改为新名字

**结果：全量 Node 90 + 浏览器 143 = 233 项全部通过。**

**给后续维护者的提醒**：凡是"靠名字判断自己人"的地方（健康检查、文件识别、日志过滤），
不要把**可改的产品名**写进判据里——用稳定的标识（这里是 `data-app` 属性）。名字是会变的。
